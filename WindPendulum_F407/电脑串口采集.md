# 电脑端串口数据采集

## Q1 网页上位机

[上位机](上位机/README.md) 用 Chrome 或 Edge 的 Web Serial 直连 J-Link VCOM。STM32 通过 USART1 接收 WP1 参数及启停命令，并在串口遥测中返回试次 ID。网页持续连接，同一端口可连续做多轮实验。每轮 START 可下发 5–60 秒运行时长，板端应答快照确认实际值。旧固件可以只读监测。

## Q1/Q2当前题目采集（2026-11-23）

题目模式使用 `Tools/q1_trial.py`，下文的 `serial_capture.py` 用于历史电机台架协议。每次会话保存 `telemetry.csv`、`raw.bin` 和 `session.json`，Q2 会话另存于 `数据记录/串口/Q2/` 并附 `fields.csv`。Q1/Q2 每次启动采集结束后写出 `analysis.json`，有有效运行快照时生成 `control_curves.png`。原始数据留本机，Git 忽略。

```powershell
# 只观测，绝不发启停命令
python -B -X utf8 Tools/q1_trial.py --problem q2 --length-cm 60 --action observe --duration 2
# 只有获得本轮明确启动授权后才运行
python -B -X utf8 Tools/q1_trial.py --problem q1 --action start --duration 30
python -B -X utf8 Tools/q1_trial.py --problem q2 --length-cm 60 --action start --duration 20
# 从旧会话补生成报告，显式提供当时的 850‰ 上限
python -B -X utf8 Tools/q1_trial.py --report-session '数据记录/串口/20261124_183449_COM9_q1_start' --historical-pwm-limit 850
```

新版板端快照为 70 列（前 68 列沿用网页试次记录格式，末两列为中心估计和居中修正），Q2 CSV 另附 19 列主机时间和派生值。派生角度单位为 °、速度为 °/s、地面坐标为 cm。P/I/D 原始 `*_milli` 数值除以 1000 得到 PWM‰，报告曲线使用 PWM 百分比。重点采集变量如下。

| 变量 | 用途 |
|---|---|
| `problem_id,target_length_mm,reference_period_ms,reference_ramp_ms` | 确认板上实际运行的题目和目标 |
| `q1_center_cdeg,q1_center_output_milli` | 最近有效左右端点中值的滤波结果（0.01°），以及加到有符号 PWM 命令上的居中修正（0.001‰） |
| `roll/pitch/target_*_cdeg`、`pitch_error_deg` | 两轴目标与实际角度及跟踪误差 |
| `roll_rate/pitch_rate/target_pitch_rate_cdeg_s`、`filtered_pitch_rate_error_cdeg_s` | 角速度反馈、参考速度和 D 项的低通滤波结果。Q1 阻尼对照版滤波的是负实测角速度，Q2 和早期 Q1 滤波的是角速度误差 |
| `p_pitch_milli,i_pitch_milli,d_pitch_milli,pid_pitch_milli` | PID分项、总输出与饱和分析 |
| `pitch_integrating,pitch_kp_milli,pitch_ki_milli,pitch_kd_milli` | 积分冻结状态与该条样本的真实增益 |
| 四路 requested/applied PWM、`pwm_limit_permille,en_command,en_pin,keys` | 实际输出、占空比上限、门控和停止键 |
| `time_ms,q1_run_ms,q1_state,q1_reason` | 板端时间、运行阶段、超时/故障/复位判断 |
| `host_rx_time,host_elapsed_s,ground_x_cm,ground_y_cm` | 主机接收时间及按已标定角度估算投影 |

遗留 q1 字段用于当前题目，Q2 运行为 mode=8。`q1_switches` 记录实际 PWM 符号交接。工具兼容 47、58、59、67、68 和 70 列。旧记录缺失的板端字段为 0 占位。补历史报告可提供当时的限幅。缺少可靠限幅时，饱和指标记为 null。Q2 启动后校验板端题号与请求长度。Python 采集器对 COM 口只接收，启停使用通过镜像哈希和烧录校验的 J-Link RAM 命令。

报告曲线使用完整捕获时间轴，保留启动前、运行中及停机后的实测角度、角速度和实际有符号 PWM（PWM1 减 PWM2）。目标角度、目标角速度及 P/D 分项绘制在运行区间内。图上用竖线标出启动和首次停机。指标包括运行态角度极值、目标及实测周期、角度跟踪 RMSE、估算地面跨度和 PWM 到限时间占比。实测周期取增幅结束后同向角度过零间隔的中位数，统计中附带间隔数量。到限时间按相邻两帧的板端运行时间差加权，使用前帧 PWM 判断，间隔超过 50 ms 的区间排除。占比是快照估计，地面跨度用姿态投影估算。

已经记录的故障试验也会生成报告，并标注停机原因。没有结束记录、复位、失联或采集失败的会话不标记有效调参数据。启动后超过 0.5 秒无有效数据即中止并尝试停止。绘图需安装 `Tools/requirements-pc.txt` 中的 Matplotlib，绘图失败时仍保留原始会话和已写出的指标。

`analysis.json` 的 `first_stop` 记录首次停机的原因、板端运行时间、姿态和 Pitch 角速度。`reference_cycles` 对 Q1 和 Q2 记录增幅结束后的完整参考周期，包含投影跨度、角度 RMSE 和相位滞后。相位按参考频率拟合目标和实测 Pitch，允许两条曲线有独立的角度偏置。正值表示实测滞后，负值表示超前。保护触发时尚未结束的参考周期排除。

首轮有效60 cm数据位于 `Q2/20261123_041719_COM9_q2_start_L60cm/`：946行遥测、698行运行快照、15秒完整结束，增益35/4/8、滤波30 ms，精度尚未达标。早期第二轮 `Q2/20261123_042747_COM9_q2_start_L60cm/` 使用30/1/12、滤波50 ms，后段幅度衰减。后续多轮继续调整，当前候选32.75/1/8、滤波50 ms已烧录并待机，等待明确启动后测试。原始CSV会话留本机；按原始CSV计算的候选依据和当前状态见根目录项目交接及 `Q2/pid_adjustment_04_60cm.json`、`Q2/pid_adjustment_05_60cm.json`。

## 电机台架28列采集器

当前 MCU 通过 USART1 的 PA9 TX 输出电机测试遥测。电脑端使用 J-Link 的虚拟串口 COM9 接收，配置为 115200、8 数据位、无校验、1 停止位、无流控。接线为：主控 PA9 TX → J-Link RX，主控与 J-Link 共地。PA10 到 J-Link TX 只在以后需要电脑向板子发送命令时使用；本采集器不会向串口写入任何字节，也没有复位控制线。打开端口前请求 DTR/RTS 为低，但 Windows 驱动打开端口时可能短暂改变控制线。

## 启动

在 `WindPendulum_F407` 目录执行：

```powershell
python -m pip install -r .\Tools\requirements-pc.txt
python .\Tools\serial_capture.py --port COM9
```

需要确认端口时执行：

```powershell
python .\Tools\serial_capture.py --list-ports
```

采集会一直运行，按 `Ctrl+C` 结束。短时间验证可以使用：

```powershell
python .\Tools\serial_capture.py --port COM9 --duration 10 --label bench
```

也可以使用 PowerShell 封装：

```powershell
.\Tools\capture_serial.ps1 -Port COM9 -Duration 10 -Label bench
```

默认输出到 `WindPendulum_F407/数据记录/串口/`，每次启动创建一个独立目录，例如 `20261116_221500_COM9_bench`。采集器可以从任意一行接入，不要求重新下载固件；如果串口暂时断开，会记录断开事件并按固定间隔重连。`-Duration 0` 表示持续采集，负数会被拒绝。

## 文件

| 文件 | 作用 |
|---|---|
| `telemetry.csv` | 可直接用 Excel 或 Python 读取的结构化记录。前 8 列是电脑端上下文，随后严格保留固件 28 列原顺序，最后附加百分比、安培、伏特和按键位解码值 |
| `raw.bin` | 串口实际收到的全部字节，包含启动横幅、协议头、坏行和停止时未完成的行 |
| `events.csv` | 连接、协议头、坏行、超长行、断开、时间回绕/复位等事件及主机时间 |
| `fields.csv` | 每列顺序、单位和含义；`pc_sequence` 是主机行号，不是 MCU 序号 |
| `session.json` | 端口配置、开始/结束时间、采集统计、协议校验状态和本地最近一次构建/烧录清单（若存在） |

采集器只把通过字段数、枚举、布尔值和范围校验的行写入 `telemetry.csv`。协议头尚未出现时，会按工程内置的 28 列协议暂时解析，并在会话元数据中标注；收到匹配协议头后会解除该标记。收到不同版本的 `time_ms,...` 协议头后会停止结构化解析，只继续保存原始字节和异常事件，避免列错位；即使之后又收到匹配头，本次会话仍以退出码 4 标记协议曾不匹配。

`board_epoch` 和 `board_event` 用于区分正常递增、uint32 时间回绕和疑似复位。它们是主机根据收到的数据推断的；断线期间的复位无法可靠观察，某些回绕和复位情形也可能相似。`connection_id` 用来区分串口重连。`timing_gap_suspected=1` 只表示相邻板端时间超过默认 250 ms，不能精确证明丢失了多少帧，因为固件协议没有序号或校验和。

## 当前 28 列协议

协议头来自 `Core/Src/diagnostics/motor1_test_stm32.c`，字段的完整单位和说明以每次会话中的 `fields.csv` 为准。`current_ma`、`current_filtered_ma` 和导出的 `current_a` 仍必须结合 `current_calc_valid`、`current_overrange`、`reference_calibrated` 判断，尚未通过实物标定时不能当作精确电流。PB1 的 U1 数值也保留 `voltage_valid`，不能仅凭 CSV 列名认定为已标定母线电压。

2026-11-17 的电流算法源码仍使用同一 28 列格式：`current_adc` 为批次最后一笔原始码，`current_valid` 表示本批采集成功，`current_ma` 为批次平均并经零点/比例修正后、尚未 IIR 平滑的电流；`current_filtered_ma` 为其 IIR 值。旧固件每批 1 笔，新源码默认 8 笔，任一笔饱和都会置 `current_overrange=1`。因此最后一笔 ADC 未到满量程也可能出现饱和标志；主机不能用最后一笔原始码重新计算并替代 MCU 批次电流。`reference_calibrated` 仅涉及 VDDA 参考，不代表零点或整条电流链已标定。本轮新固件未下载，不能把旧会话说成新算法实测结果。

## 验证与限制

采集器的解析测试位于 `tests/test_serial_capture.py` 和 `tests/test_serial_receiver_io.py`，共 16 项，覆盖合法行、半行、坏行、协议头变化、时间回绕、复位、断线重连和保存失败。它没有修改 MCU 工程；实际串口接收是否有数据仍取决于 PA9 到 J-Link RX、共地、板子供电和 COM9 枚举状态。J-Link 能下载 SWD 不等于 USART1 已经接通。实测会话 `数据记录/串口/20261116_223541_COM9_pc_receiver_fixed` 收到 100 行、0 条坏行、9571 字节，板端间隔为 100 ms；停止瞬间保留了 1 字节未成行数据在 `raw.bin` 中。

当前文档和采集器只支持电机1测试的 28 列协议。尚未把 IMU、姿态融合或 Q1–Q7 题目遥测接入该解析器；后续协议确定后应增加独立字段版本或适配器，不能直接套用本协议的列含义。
