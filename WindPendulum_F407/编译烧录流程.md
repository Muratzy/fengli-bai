## 直接执行

在项目根目录 `风力摆项目` 打开 PowerShell：

```powershell
# 完整编译 Debug，成功后下载、校验、复位并运行
pwsh -NoProfile -ExecutionPolicy Bypass -File .\WindPendulum_F407\Tools\build_flash.ps1 -Action BuildFlash

# 只编译，不连接开发板（也是脚本的默认动作）
pwsh -NoProfile -ExecutionPolicy Bypass -File .\WindPendulum_F407\Tools\build_flash.ps1 -Action Build

# 只读寄存器：不暂停、不复位、不修改 PWM、不模拟按键
pwsh -NoProfile -ExecutionPolicy Bypass -File .\WindPendulum_F407\Tools\build_flash.ps1 -Action Inspect
```

如果已经进入 `WindPendulum_F407` 目录，脚本路径改为 `.\Tools\build_flash.ps1`。脚本根据自身位置定位工程，工作目录可任意；Windows PowerShell 也可将 `pwsh` 替换为 `powershell`。

## 脚本具体做了什么

1. 调用 CubeIDE 的 headless builder 导入原工程并完整构建 Debug；使用工程自己的 include、源文件配置、宏、链接脚本和 IDE 自带工具链。
2. 同时检查进程退出码、`Headless build completed successfully` 和新 ELF 的更新时间；构建失败即终止，避免下载残留旧镜像。
3. 记录 ELF 的 SHA-256，复制到 ASCII 暂存目录并核对哈希。
4. 调用 J-Link，通过 SWD 下载 ELF 并检查 Flash 校验结果，随后复位运行。不发送启转命令，是否输出由本次固件逻辑决定。
5. 保存日志和包含哈希、工具路径、探针及下载结果的 `build/workflow/last-run.json`。

实际编译调用的等价命令：

```powershell
& 'C:\cubeIDE\STM32CubeIDE_1.19.0\STM32CubeIDE\stm32cubeidec.exe' `
  --launcher.suppressErrors -nosplash `
  -application org.eclipse.cdt.managedbuilder.core.headlessbuild `
  -data 'C:\Temp\WindPendulumCubeIDE' `
  -import 'C:\Users\Muratsy\Desktop\风力摆项目\WindPendulum_F407' `
  -cleanBuild 'WindPendulum_F407/Debug' -printErrorMarkers
```

实际下载调用的等价命令：

```powershell
& 'C:\Users\Muratsy\SEGGER\JLink_V962\JLink.exe' `
  -device STM32F407VE -if SWD -speed 4000 -SelectEmuBySN 602712599 `
  -autoconnect 1 -NoGui 1 -ExitOnError 1 `
  -CommanderScript 'C:\Temp\WindPendulumTools\flash.jlink'
```

`flash.jlink` 由脚本生成，内容为：

```text
r
loadfile "C:\Temp\WindPendulumTools\WindPendulum_F407.elf"
r
g
exit
```

`loadfile` 执行擦写/比较及校验，`r` 复位，`g` 运行。构建后的 ELF 包含代码、数据及调试符号，无需先转换成 HEX。COM9 是日志通道，实际下载走 J-Link SWD。

## 结果与寄存器读回

| 文件 | 用途 |
|---|---|
| `build/workflow/cubeide-build.log` | 完整构建日志及 IDE 错误标记 |
| `build/workflow/jlink-flash.log` | 探针连接、擦写、校验及复位运行记录 |
| `build/workflow/jlink-inspect.log` | 非暂停寄存器读取 |
| `build/workflow/last-run.json` | 最近一次成功构建的镜像哈希；`flashVerified=true` 表示该镜像已通过下载校验 |

日志为最近一次对应操作的记录，失败时以脚本错误和当前日志为准；失败操作不会将旧的 `last-run.json` 更新成成功。以上文件属于构建输出，由 Git 忽略。

`Inspect` 第一组从 `0x40010028` 起的 7 个值依次为 TIM1 的 `PSC/ARR/RCR/CCR1/CCR2/CCR3/CCR4`。20 kHz 测试的期望为 `0/8399/0/0/0/0/0`（待机）；输出以十六进制显示，`8399 = 0x20CF`。

`0x40020C10` 起两个值分别为 GPIOD 的 IDR/ODR，bit7 对应 EN；测试模式正常待机时 ODR bit7=1，IDR bit7 显示 EN 线的实际数字电平。若 ODR=1 但 IDR=0，检查板上保护下拉及连线，不把它记录成 EN 已实测为高。GPIOC IDR 的 bit13/bit0/bit1 对应 KEY1/2/3，低电平为按下。独立看门狗的 PR/RLR/SR 正常为 `3/499/0`。

## 已解决的问题

- `-import` 必须使用 Windows 反斜杠路径，`C:/...` 曾被 CDT 当作 URI scheme 而导入失败。
- 使用 `stm32cubeidec.exe`，此前批处理入口存在路径编码问题。
- `Core/Src/syscalls.c` 提供弱定义的无文件后端接口，避免 nosys 的链接 NOTE 被 IDE 错误解析成构建错误。日志通过 HAL UART 发送。
- 当前仍有一条继承链接脚本的 RWX LOAD 段警告；构建退出码为 0，它不代表下载失败。
- `.cproject` 中继承的同名 Debug 配置会产生重复构建日志；以最终退出码和成功标记为准，不为此改写已有工程配置。
- 测试固件看门狗在调试暂停时也计时；长时间打断点会复位。`Inspect` 全程不暂停内核，不附加 `g` 命令，避免“CPU is not halted”提示。
- SWD 下载成功不自动证明 COM9 已与 USART1 连通；本次已将 PA9 TX 接 J-Link RX 并共地验证，COM9 能收到连续 CSV。原理图“串口1”PC6/PC7 实际为 USART6，不能作为 PA9/PA10 的替代。
- 若探针可识别且 VTref 正常，但出现 `Failed to initialize DAP`，先检查开发板是否连接、SWDIO/SWCLK/GND 和供电，必要时用 `-SpeedKHz 1000`。2026-11-16 曾因开发板暂未连接而停止下载，不能将编译成功记录成新版已烧录。

在 CubeIDE 图形界面中仍可正常导入本工程、构建 Debug，并选择 J-Link / STM32F407VE / SWD 下载。本脚本使用的也是同一个 IDE 工程和工具链。
