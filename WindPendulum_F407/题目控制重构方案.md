## 2. 重新确立的系统原则

1. **题目是产品主线。** OLED 只选择题目、设置参数、发出开始/停止/返回命令并显示结果；UI 不运行控制循环，不直接写 PWM。
2. **一问一个实例。** 系统同时只允许一个活动题目，题目实例拥有自己的参数、阶段、计时器、统计量和结果。
3. **控制链共享。** IMU 采样、安装坐标变换、固定零偏、姿态融合、双轴控制器、四电机混控和安全门控属于公共服务，由题目提供目标轨迹。
4. **MotorTask 是唯一执行器写入者。** 题目块和控制器只产生受限的 `ActuatorCommand`；只有 MotorTask 能写 TIM1 四路比较值、PD7 EN、PD8 激光和 PD12 蜂鸣器。
5. **控制证据与比赛证据分开。** IMU 姿态投影可用于闭环和调试，但不能单独证明地面激光轨迹达标。长度、直线度、方向、半径和重复性必须用地面标尺、激光点记录或录像验证。
6. **高频链路与显示、串口解耦。** 控制链按固定周期运行，OLED 目标刷新 100 ms，串口使用快照/事件队列；阻塞式显示或串口发送不能拖慢控制。
7. **所有退出都经过同一安全路径。** 取消、超时、IMU 过期、角度/角速度超限、EN 异常、故障输入、任务异常均进入 `SAFE_STOP`，清零 PWM，并按题目模式的门控策略撤销 EN，再锁存原因。Q2 待机/停止的当前策略是 EN 低；电机1台架配置仍遵守用户确认的 EN 默认高、PWM 为零，两种模式不能混用输出策略。

## 3. 统一数据模型

后续不要让每道题继续扩展 `PendulumTelemetry` 中的题目专用字段。先建立公共模型，遥测和 OLED 都从模型生成视图。

### 3.1 输入快照 `ProblemInputs`

```text
timestamp_ms
imu_online / sample_valid / sample_age_ms
roll_deg, pitch_deg
roll_rate_dps, pitch_rate_dps
accel_weight, direction_deg, tilt_deg, direction_valid
driver_ok, motor_enable_feedback, user_stop
```

输入由 FusionTask 发布，带 MCU 时间戳和有效标志。实时快照允许覆盖旧值；开始、停止、故障和完成事件使用独立事件队列，不能因覆盖丢失。

### 3.2 轨迹目标 `TrajectoryTarget`

```text
target_x_m, target_y_m
target_vx_mps, target_vy_mps
target_ax_mps2, target_ay_mps2
target_roll_deg, target_pitch_deg
target_roll_rate_dps, target_pitch_rate_dps
phase, reference_valid
```

地面坐标约定为：`x` 向右，`y` 向上；方向角从上方为 0°、顺时针增加。以摆轴到激光落点平面的高度 `H` 为几何参数，采用

```text
theta_x = atan2(x, H)
theta_y = atan2(y, H)
x       = H * tan(theta_x)
y       = H * tan(theta_y)
```

控制器跟踪角度和角速度，地面位置和速度用于生成目标、遥测和结果统计。`H`、激光同轴关系和坐标零位必须经过实物标定后才能冻结。

### 3.3 控制与执行器模型

`ControlFeedback` 保存每轴 PID 的 P/I/D、积分是否允许、饱和状态、目标/实际角速度和控制周期。`ActuatorCommand` 至少包含：

```text
pwm_permille[4]
enable_request
laser_request
buzzer_event
command_timestamp_ms
valid / reason
```

`ProblemResult` 保存题号、试次号、参数、开始/结束时间、完成状态、故障码以及题目特有指标：直线长度、中心偏差、方向误差、半径误差、圈数、恢复时间、重复性统计等。

## 4. 统一题目生命周期

所有 Q1–Q7 使用同一状态机。题目块的 `step()` 必须是有界、快速、可重复调用的函数，不能 `HAL_Delay`、等待按键或直接访问 HAL。

```text
IDLE
  -> SELECTED
  -> CONFIGURING
  -> PRECHECK
  -> ARMED
  -> RAMP_UP
  -> TRACKING
  -> VERIFY
  -> COMPLETE | TIMED_OUT | FAILED | ABORTED
  -> SAFE_STOP
  -> RESULT
  -> IDLE
```

- `SELECTED/CONFIGURING`：只编辑参数，不允许执行器输出。
- `PRECHECK`：检查 IMU 身份和在线状态、固定零偏/安装坐标有效、数据未过期、参数在范围内、驱动器无故障、PWM 为零且 EN 符合题目模式安全初始值。
- `ARMED`：明确等待开始确认；Q2 题目模式 EN 保持低，开始边沿只由题目管理器接受一次。
- `RAMP_UP`：平滑建立目标幅度或基准推力，记录实际开始时间；不能把启动斜坡期间的轨迹算作达标样本。
- `TRACKING`：按题目轨迹运行，周期性更新控制和中间统计。
- `VERIFY`：在连续窗口内检查完成条件，避免单个瞬时峰值触发成功。
- `COMPLETE`：锁存结果并生成声/光提示请求。
- `TIMED_OUT/FAILED/ABORTED`：锁存未达标、故障或用户停止原因。
- `SAFE_STOP`：统一清零四路 PWM、将题目模式 EN 拉低、关闭激光；MotorTask 确认输出后才进入 `RESULT`。电机1台架测试的 EN 默认高属于独立测试配置，不改变题目模式安全状态。

## 5. 公共控制链

### 5.1 采样与融合

当前工程已经有 `ImuTask → FusionTask → TrajectoryTask → MotorTask → TelemetryTask` 链路，IMU 采样周期目标为 2 ms。后续保持 FreeRTOS 任务和单向队列，不把参考工程的 1 ms PIT 中断方案搬进来。

FusionTask 的顺序固定为：读取 ICM-45686 原始值、扣除 `app_config.h` 固定陀螺仪零偏、变换到摆体坐标、执行姿态融合、计算角速度和有效性。加速度权重应根据加速度模长和角速度变化门控；IMU 过期时控制链立即失效，不能继续沿用上一帧 PWM。

### 5.2 轨迹生成

轨迹生成器只输出 `TrajectoryTarget`，不直接选择电机。直线使用单轴正弦或自然摆周期参考，并用半余弦包络从静止平滑增幅；方向题把一条单轴轨迹旋转到设定方向；圆周使用两轴正交相位：

```text
x(t) = R * cos(phi(t))
y(t) = R * sin(phi(t))
phi(t) = phi0 + omega * t
```

目标速度和角速度用解析式计算，避免对带噪角度做直接差分。周期、增幅时间、半径、旋向、目标长度和超时均为题目参数，必须有单位和范围校验。

### 5.3 双轴控制器

每个轴各有一套 PID，控制律采用角度误差加角速度反馈：

```text
u = Kp * (theta_ref - theta)
  + I
  + Kd * LPF(rate_ref - rate)
```

保留当前 `PID_UpdateWithRate()` 方向，但重构时明确以下规则：

- I 项仅在传感器有效、输出未饱和、执行器斜坡未发生方向切换时累积；
- 达到输出限幅或发生故障时进行 anti-windup，并冻结或清除 I 项；
- D 项使用角速度反馈和低通滤波，不对 OLED/串口快照差分；
- 控制周期使用实际时间差并做上下限保护；
- 控制器输出先经过混控矩阵，再由 MotorTask 做最终限幅和门控。

### 5.4 四电机混控和方向标定

混控使用集中配置的 `fan_mix[4][2]` 矩阵，不在 Q1/Q2 内写死电机编号。现有实物确认只作为当前标定记录：电机板 PWM1 开启使摆体向右，PWM2 开启使摆体向左；PWM3/PWM4 的上下方向和正负号尚未完成实物验证，不能提前启用。

每个相反推力对必须满足：先把旧侧降为零，确认一个控制周期内无旧输出，再升新侧；同一对禁止同时导通。PWM 使用 0–1000‰，启停斜坡属于执行器服务参数，不属于题目算法。EN 只由 MotorTask 控制：题目模式开始前/停止后保持低，获准运行后拉高；换向、故障和停止都有明确的 break-before-make/输出清零路径。台架测试 EN 默认高的历史行为仅在独立测试配置下保留。

## 6. 各题任务块设计

| 题目 | 轨迹/控制任务 | 进入条件 | VERIFY 判据 |
|---|---|---|---|
| Q1 自由摆直线 | 以实测自然周期为基准的单轴对称摆动；端点地面总长至少 50 cm（幅值至少 25 cm） | 中心附近、IMU 有效、周期参数有效 | 连续完整周期的地面轨迹长度、直线度和中心偏差均满足要求；记录重复试次 |
| Q2 可调直线 | 目标总长 `D=30–60 cm`，地面幅值 `A=D/2`，以 `x(t)=A sin(phi)` 生成目标，目标轴可选 | 目标长度、摆轴到地面的几何标定有效 | 连续完整周期长度误差不超过 ±2.5 cm；15 s 内完成并记录重复性 |

| Q6 抗风扰 | Q5 圆周运行时施加水平风扰：台扇距摆体 1–2 m、额定功率 50–60 W、风速 1.0–2.0 m/s，持续 5 s；记录风扰开始/停止事件 | Q5 已达到合格圆周，外部风速和距离满足题目条件 | 停风时间戳起 5 s 内恢复 Q5 的圆环误差判据；记录恢复时间和轨迹 |

Q1/Q2 现有代码可作为算法原型和遥测来源，但它们当前的“窗口到时”不等于题目达标。重构时必须把连续周期稳定性、结果锁存和 `VERIFY` 阶段加入统一管理器。

## 7. FreeRTOS 任务和队列边界

| 任务 | 所有权 | 目标周期/行为 |
|---|---|---|
| `ImuTask` | ICM-45686 总线 | 约 2 ms；发布原始样本和有效标志 |
| `FusionTask` | 安装坐标、零偏、姿态融合 | 跟随最新样本；发布带时间戳的 `ProblemInputs` |
| `ProblemManager/TrajectoryTask` | 当前题目实例、生命周期、轨迹和控制调用 | 固定控制节拍；处理开始/停止/故障事件 |
| `MotorTask` | TIM1 PWM、PD7 EN、PD8 激光、故障门控 | 约 5 ms 以内响应；无有效新命令即安全停机 |
| `TelemetryTask` | 串口快照和试次记录 | 20 ms 或更慢；不能阻塞控制任务 |
| `UI Task` | OLED、按键和页面模型 | 100 ms；只发命令、读快照 |

实时快照使用单槽覆盖队列；命令、取消、故障、完成和风扰事件使用事件队列或任务通知。共享结构由单一任务写入，其他任务只读队列副本。

## 8. OLED 产品流程

```text
主菜单
  -> 基本要求(Q1-Q4) / 发挥部分(Q5-Q7)
  -> 选择题目
  -> 参数页
  -> 执行前检查页
  -> 等待开始
  -> 运行页
  -> 结果页
  -> 返回主菜单
```

运行页只显示摘要：题号、阶段、已用时间、目标/实际角度或半径、PWM 摘要、IMU/驱动器状态和停止原因。OLED 100 ms 刷新不改变控制周期。按键硬件映射固定为 KEY1=PC0、KEY2=PC1、KEY3=PC13；具体的确认、参数调整和停止语义由 UI 状态机统一定义，不能让不同题目各自解释同一按键。

## 9. 验收与数据记录

每次试次至少保存：题目和参数、固件版本、试次编号、开始/结束/退出原因、IMU 有效率、目标/实际姿态、目标/实际 PWM、EN 状态、控制器 P/I/D、内部投影轨迹和外部测量文件路径。

内部遥测用于回答“控制器是否跟上目标、是否饱和、是否丢样本、何时进入故障”。外部测量用于回答“地面画线是否达标”。直线至少记录端点、拟合直线最大横向偏差、总长度、方向和重复试次；圆周至少记录中心、半径、六个均匀方位、圈数和恢复时间。没有地面标尺或录像证据时，只能报告内部估计，不能报告题目通过。

## 10. 从当前工程到新架构的实施顺序

1. 先增加公共题目数据模型、生命周期枚举、结果结构和题目注册表；保留现有 Q1/Q2 API 作为兼容入口。
2. 把 `pendulum_app.c` 中题目调度、控制调用和 MotorTask 的数据边界收敛到 `ProblemManager → ControlService → MotorTask`，不一次性搬动 CubeMX/HAL 文件。
3. 为轨迹生成器、几何换算、PID anti-windup、混控互锁建立主机侧纯算法测试；电机关闭时验证目标角、目标速率、符号和限幅。
4. 完成 PWM1/PWM2 的方向和推力标定，再验证 PWM3/PWM4；没有标定的通道保持零输出。
5. 将 Q2 原型升级为带 `RAMP_UP/TRACKING/VERIFY/RESULT` 的正式题目块，再实现 Q3 方向直线和 Q4 制动。
6. 四路混控经过台架验证后实现 Q5 圆周，再加入 Q6 风扰开始/停止事件和恢复判据。
7. 最后把 Q1–Q7 注册表、参数页、运行页、结果页接入 KK_UI；保持 OLED 100 ms 刷新，并用电脑端采集器保存每次试次。
8. 每完成一个题目，先做离线算法检查，再做无桨/单路/小占空比台架验证，最后才做整题启动；编译、烧录和启动仍按现有流程并以明确授权为前提。

## 11. 参考工程的借鉴结论

### 保留为设计思想

- 固定周期的“采样/融合/控制/输出”链路；
- 用正弦目标生成直线摆动、用两轴正交目标生成圆周；
- 两个摆动轴分别控制后再做四电机混控；
- 电机输出统一限幅，并在姿态异常时安全清零；
- 菜单配置 PID、长度、方向和半径，运行中显示状态并用蜂鸣器提示。

### 明确不移植

- 在 PIT 中断内执行 I2C 读取、姿态融合、PID 和 PWM；
- 依赖大量全局变量和 `Mode.para[][]` 无类型参数数组；
- MPU6050 的寄存器、采样率、滤波和坐标符号；
- 直接复制参考工程的 PID 数值、经验方向修正表或摄像头图像跟踪；
- 让 LCD/按键处理与题目控制循环共享状态或直接写电机。

这份文档确定了后续重新实现题目的公共边界。任何新增题目、算法或 UI 页面都应先回答：它产生什么目标轨迹、需要哪些输入、由哪个任务写执行器、如何安全退出、用什么连续判据完成，以及哪些数据由地面实测验证。
